# 战纹 · 竖屏 RTS

96×96 格（3840² 世界）的方形大地图即时战略：对角（1v1）或三角（3 人）布局，
你在己方角落发展基地，自由相机（双轴平移 + 缩放 + 小地图导航）纵览战场，推平敌方城堡获胜。
架空中世纪欧洲题材：蓝衫军（玩家）、红衫军、金衫军争夺草原上的金矿与关隘。
手机浏览器与电脑浏览器均可直接游玩（后续可用 Capacitor 打包上架）。

## 运行

```bash
npm install
npm run dev        # 开发服务器（局域网可访问，手机同网直接开玩）
npm run test       # Vitest 单元测试（模拟核心）
npm run typecheck  # 仅类型检查
npm run build      # 产物构建（dist/，任意静态托管可部署）
npm run balance    # 无头平衡跑批（见「平衡校准」）
```

## 玩法

- **胜负**：摧毁敌方城堡即胜，己方城堡被毁即败。
- **经济**：城堡被动产钱；地图上有 16~19 个金矿脉（中路与各条路线上的矿点可争夺），花 100 黄金在矿脉上建 **金矿**（+4/s）。
  黄金即兵力。方形小地图可总览战局、点按跳转视野。
- **建筑**：金矿（经济）/ 军营（解锁造兵，可多建并行排队）/ 箭塔（防守）/
  **军械库**（400，解锁 T2）/ **攻城工坊**（900，解锁 T3）。
  建筑只能在自己的建造区放置（金矿除外，可争夺公共矿点），有施工时间，施工中可被摧毁。
- **兵种（三档，dps/人口 随档位递增——升本实实在在变强）**：
  T1 步兵（50，10 dps/人口 基准）/ 弓手（80 远程）/ 重装（200 攻城盾卫，克步兵、对建筑 ×1.5）；
  T2 长枪兵（160，11.4，克骑士 ×1.8）/ 骑士（240，12.0，全场最快袭扰，克弓手 ×1.5）；
  T3 投石车（420，对建筑 104 dps + 90px 溅射，射程压箭塔）/ 近卫军（450，13.0，
  28% 全伤害减免——有效血 639/人口）。
  人口上限 80。
- **科技攒钱**：矿线达标而科技建筑未建时，AI 与跑批脚本会自动压住出兵攒金
  （真人请自行权衡：断兵 10 秒换一座军械库）。
- **克制网**（只作用于单位互打，打建筑按基础伤害；投石车/重装例外，有建筑加成；数值集中在 `config.ts`）：

  | 攻击方 | 受击方 | 倍率 | 直觉 |
  |---|---|---|---|
  | 弓手 | 重装 | ×1.6 | 远程风筝慢速重甲 |
  | 重装 | 步兵 / 建筑 | ×1.5 | 攻城盾卫 |
  | 步兵 | 弓手 | ×1.5 | 便宜快速贴脸切后排 |
  | 长枪兵 | 骑士 | ×1.8 | 枪阵反骑 |
  | 长枪兵 | 重装 | ×1.2 | 破甲 |
  | 骑士 | 弓手 | ×1.5 | 高速切后排 |
  | 投石车 | 建筑 | ×3.0 | 攻城核心武器 |

- **固守 / 撤退**：选中部队后底部出现这两个按钮。
  - **固守**：只打已进入射程的目标，绝不脱战追击（配合箭塔防守很好用）。
  - **撤退**：完全脱战撤回己方城堡，抵达后转为待命。
- **操作**：所有移动指令都是**攻击型移动**，部队沿途自动交战。
  - 缩放：滚轮或 ± 键缩放（电脑）/ 双指捏合（手机），小地图点击/拖动跳转任意角落；
    空格键跳到最近交战点/己方军队，C 回城堡。渡口在河上发光标记——咽喉要地。
  - 触屏：单指拖动平移镜头；点选部队 → 点目标下令；双击部队选中视野内同类；
    底部「全选」一键选中全军；「集结」设定全局集结点；**双击军营**可单独给它设一个集结点，
    实现多路出击；建筑先点按钮再点地图定位，✓ 确认。
  - 鼠标：左键点选 / 框选（空地拖动），右键下令、右键拖动平移；WASD/方向键平移；Esc 取消。

## AI 对手

三档难度（简单 / 普通 / 困难）：收入倍率、扩张上限、进攻波次与撤退决策均不同。
AI 会铺矿扩张 → 攒兵 → 达到阈值后波次进攻；家被偷会全军回防；战损过大且开启撤退时会收缩。

## 操作与界面

- **热键**：`Q/E/R/T/Y/B` 建造 · `1-7` 出兵 · `F` 全选 · `G` 集结 · `U/I` 升级塔/矿 ·
  `H` 固守 · `X` 撤退 · `Tab` 循环告警 · `空格` 跳交战 · `C` 回城堡 · `P` 暂停 · 方向键平移
- **编队**：`Ctrl+1..5` 编队，`1..5` 召回（空槽自动回落为出兵热键），双击跳编队质心；
  左下编队栏触屏可点
- **移动语义**：右键=移动（沿途自动接战、自动分层）；`Shift+右键`/双指轻点=强制移动
  （不接战拉扯）；`A+左键`=攻击移动
- **建造 QoL**：`Shift+点击` 连续放置；中原箭塔 `Shift+拖动` 沿线筑塔；幽灵实时提示不可建原因
- **昼夜循环**：10 分钟一昼夜（黄昏/夜晚/黎明色温），设置可关
- **信息与引导**：目标链（随局势打勾）、分级消息流、选中信息面板、兵种图鉴（数值实时生成）、
  开局对手文明情报、结算胜因
- **设置面板**（暂停屏）：主/音乐/音效三轨音量、屏幕震动、边缘滚动、目标链、伤害数字、昼夜——全部实时生效并持久化

## 模式

- **1v1 对战**：玩家对阵单个 AI，三张图轮换，对角出生（西南=玩家 / 东北=敌方），建造区贴角点对称。
- **3 人混战（1 人类 + 2 AI）**：三方城堡构成**等边三角形**（外接圆半径 1350，质心即地图中心的"王冠之地"），
  任意两方间距完全相等 —— 公平性由几何保证。矿点绕质心精确 120° 旋转对称，
  三方到每个矿点的距离一致；两个 AI 的建造与出兵参数对称缩放（`ai.ts` 的 `scale` / `waveScale`）。
  AI 的行动完全身份盲：目标只按距离选，分辨不出对手里谁是玩家。
  **王冠之地终局**（`CROWN_WINDOW = 360s` 开窗）：此后质心 350 内唯一驻军 ≥12 人口
  持续 45 秒即胜；开窗前 30 秒 HUD 预告，AI 残局也会主动进军争夺。
  这是防僵局与防雪球的双保险——AI 互殴 5-6 分钟分出胜负后，落后方仍有抢王冠的翻盘出口。
  联机对战暂不在这版范围内（内核已为它打好基础）。

## 架构（为联机留后路）

```
src/
  core/    确定性模拟核心（纯 TS，无 DOM）：固定步长 60Hz，种子随机，
           所有操作都是 Command 对象（未来联机只同步指令流即可 lockstep）
    sim.ts         世界状态 / 指令 / 移动战斗 / 经济生产 / 胜负 / 状态指纹 / 序列化
    pathfinding.ts A* 寻路（8 向 + 视线平滑）+ 最近可用格
    ai.ts          AI 状态机（侦查反制 / 扩张 / 波次 / 回防 / 溃退）
    config.ts      全部数值（单位 / 建筑 / 地图 / 难度）集中在此，便于平衡
    types.ts       数据结构；Command 带可选 tick，为联机留口
  render/  Canvas 2D 渲染层 + 相机 + 特效 + 小地图（纯视觉，不影响模拟）
    shapes.ts      形状与配色的唯一绘制源，战场与 HUD 卡槽共用
  input/   触屏 / 鼠标统一映射为 Command
  ui/      DOM HUD（顶栏 / 卡槽 / 提示 / 结算）
scripts/
  balance.ts       无头跑批，用于量化数值改动的影响
```

渲染为程序化绘制的架空中世纪风：草原荒野、泥土路、城堡要塞、金矿脉、羊皮纸 UI。
配色（蓝衫军蓝 / 红衫军红 / 金衫军金，资源为奶白金）集中定义在 `shapes.ts`；
`core/` 与渲染完全解耦，可整体迁移到 PixiJS。

**单位辨识**用两个正交通道：阵营 = 颜色（填充 + 底环），兵种 = 轮廓形状 + 尺寸 + 徽记 +
职业道具（随朝向旋转的剑盾 / 弓箭 / 骑枪）。步兵 = 圆盾持剑 / 弓手 = 箭头张弓 /
重装 = 骑士盾骑枪 + 盔羽；徽记与盔羽**不随朝向旋转**，否则朝向一变剪影就变，
在小屏上根本认不出来（这是早期的实际教训）。改外观请走 `render/shapes.ts`，
不要动 `UNIT_DEFS.radius` —— 那是碰撞、分离与射程判定用的，动了就会影响平衡。

## 确定性约束（改动内核前必读）

联机 lockstep 的前提是「同种子 + 同指令流 ⇒ 逐位一致的状态」，因此：

- **不要用 `Math.hypot`**。它的实现跨 JS 引擎（V8 / JSC / SpiderMonkey）不保证位精确，
  一个 ULP 的差异就会翻转索敌比较，进而蝴蝶效应导致不同步。
  统一写成 `Math.sqrt(dx * dx + dy * dy)`（`sqrt` 与四则运算是 IEEE754 精确定义的）。
- `Math.atan2` 只影响 `facing`（纯朝向渲染），可以保留。
- 随机数一律走 `rng.ts`（mulberry32），状态存在 `World.rngState`，**禁用 `Math.random`**。

`tests/determinism.test.ts` 守着这条底线：同种子跑两遍、同指令流跑两遍、序列化往返后
继续推进，三者的状态指纹都必须一致。`hashWorld()` 提供指纹，联机时每 N 帧比对一次
即可第一时间发现 desync。

## 平衡校准

改完 `config.ts` 不要靠感觉判断好坏，跑一遍无头跑批：

```bash
npm run balance -- 14 600        # 每档 14 局，单局上限 600 秒
ZW_NO_COUNTER=1 npm run balance  # 关闭兵种克制，用于 A/B 对照
```

脚本内置一个"脚本玩家"（每 0.6 秒决策一次，模拟普通玩家节奏），输出三档难度下的
玩家胜率、平均时长、平均击杀，同时给出"玩家完全不操作"的摆烂基线。
出击门槛按人数走：1v1 攒 30 人口、3 人局攒 12 人口（贴身消耗战里攒不出 30）。

**阵型辅助（默认开）**：下令移动时自动分层——近战在目标点、远程拖后 70、骑士前压 40
（行军成锋线、接战近战先顶）；新兵默认自动奔赴军队质心（点「集结」设固定点即关闭）；
「前排 / 后排」按钮一键全选对应角色。跑批显示阵型分层显著提升攻城效率
（1v1 困难档脚本胜率 8% → 58%）。

当前基线（每档 12 局、600 秒上限、对应人数地图轮换）。96×96 大图上脚本玩家已带科技线：
扩矿 8 座 → 军械库（T2 长枪兵/骑士）→ 攻城工坊（T3 投石车/近卫军）、攒到接近满编
（50/80 人口）出击、先拆矿后推家、矿线遇袭全军回防 —— 它模拟的是一个会防守经济、
懂科技节奏、懂雪球的普通玩家。节奏：1v1 普通 ~7.6 分钟、3 人 ~9 分钟。

**1v1（三张双人图轮换）**

| 难度 | 玩家胜率 | 平均时长 | 平均击杀 | 超时 |
|---|---|---|---|---|
| 简单 | 100% | ~276s | ~57 | 0/12 |
| 普通 | 42% | ~460s | ~119 | 3/12 |
| 困难 | 8% | ~513s | ~149 | 4/12 |

> 困难档超时高是当前已知边界：困难 AI 经济滚雪球后双方互啃不动，僵持到上限。
> 对真人是否同样成立待实机反馈；若要调整优先动困难 AI 的 `incomeMult`。

**3 人混战（1 人类 + 2 AI，两张三人图轮换，含王冠终局）**

| 难度 | 玩家胜率 | 平均时长 | 平均击杀 | 超时 |
|---|---|---|---|---|
| 简单 | 100% | ~416s | ~86 | 0/12 |
| 普通 | 58% | ~406s | ~113 | 0/12 |
| 困难 | 25% | ~427s | ~125 | 0/12 |

> 三人局的教训：扩张最快的一方会同时成为两个 AI 的最近袭击目标（前沿矿线=活靶子），
> 主动分兵出击等于把兵力对半送——脚本玩家的正确打开方式是开窗前龟缩扩张攒兵、
> 开窗后全军压向王冠之地。这也是推荐给真人玩家的三人局思路。

> 大图平衡的三条新经验：
> 1. **`waveMax` 必须大于跨图行军时间**（速度 ×1.4 后约 55s），否则 AI 波次在半路就超时收兵；
> 2. **防守方有零距离援军优势**，半军出击就是送死 —— 进攻要攒到接近满编，且先拆矿断经济再推家；
> 3. **矿多收入高时人口上限才是真约束**：黄金盈余让损失瞬间补满、会战结果无法累积，
>    把 `POP_CAP` 提到 80 让「补充速度」重新成为稀缺资源，僵局才会瓦解。
> 胜率在 12 局样本下噪声 ±15%，以实机体验为准。

三档必须**单调更强**（收入 / 金矿上限 / 军营数 / 箭塔数 / 波次规模递增，`waveCd` 递减），
否则难度选择会失去意义。

三个踩过的坑，写在这里免得重蹈：

- **`waveCd` 是个弱杠杆**。AI 重建一支 20 人口的部队远比 `waveCd` 慢，所以真正决定
  进攻节奏的是产能而非冷却。曾经把困难的 `waveCd` 调得比普通还长，两档直接挤在一起。
  调难度优先动 `incomeMult` / `maxMines`。
- **AI 的经济优先级必须高于造兵**。曾经因为造兵把黄金花光，AI 全程卡在 2 座金矿、
  永远缺钱，被玩家 100% 碾压。现在金矿优先级最高，并给扩张预留预算。
- **这个平衡点处在临界区**。建造区从"前压下不对称"改回"中线对称切分"后，玩家可用纵深变大、
  加上集结点对称化把碰撞线推向玩家，普通档胜率一度从 80% 塌到 0%。
  所以用"玩家大踏步前压、AI 贴基地集结"的不对称集结点把碰撞线拉回玩家半场，
  再用难度数值重新校准。过程里 `incomeMult` 每动 0.05 都能让胜率整片翻转，调参要小步、每次跑批。
- **三人图的「家被入侵」半径是节奏杀手**。三角几何下各家前哨矿与邻居的集结部队相距
  ~220-300，沿用 1v1 的 300 判定半径会让两个 AI 从第 1 分钟起就互相视为"来犯之敌"、
  永久锁死在防御态（`waves=0` 打满全场），全员对峙到超时。三人图收紧到 180，
  只有真正踩到建筑才算入侵。
- **三人局本质是消耗战均衡**：金矿 25 秒回本，袭扰密度赶不上重建速度时经济均衡永远
  破不了——所有人的兵力被绞肉机压在几个人口、城堡一根毛都掉不了。波次门槛要压到
  消耗战均衡之下（×0.25）、间隔要压过重建速度（×0.6）、集结点要退回家门口让军队能
  攒出拳头。另外城堡血量在 1v2 里是**玩家的容错**，为了"对局好收尾"而降它反而直接掉胜率。

另外**波次必须有终点**：曾经波次只在"部队被打残 65% 或全灭"时才结束，首波一旦占上风
AI 就无限续攻，`waveCd` 永远不会被写回、"波次进攻"名存实亡。现在每波有 `waveMax` 上限。

## 地图

开局按种子从对应人数的图里轮换（`config.ts` 的 `MAPS`，目前 3 张双人图 + 2 张三图），
全部是 96×96 格方形大图，每张的战术侧重不同：

| 地图 | 人数 | 特征 |
|---|---|---|
| 中央关隘 | 1v1 | 对角布局，中央隘口收窄 —— 控住中路就控住对方的经济动脉 |
| 开阔平原 | 1v1 | 几乎没有掩体，机动与包抄决定胜负，也最容易被绕后 |
| 富矿之争 | 1v1 | 中央矿脉密布 —— 谁吃下中心，谁就吃下整场比赛 |
| 三足鼎立 | 3 人 | 三方等距鼎立，岩脊分割三路 —— 控住隘口就掌握节奏 |
| 中原逐鹿 | 3 人 | 岩石稀疏的等距三角 —— 没有地形可依，扩张速度决定一切 |

地图是纯数据，改起来容易埋雷，所以 `tests/maps.test.ts` 钉住了约束：
矿点不越界、不压在岩石上；任意两方城堡互相连通；每个矿点至少能从一方城堡走到。
对称性按人数分两类 ——
双人图矿点与岩石关于地图中心点对称（出生点对角）；三人图三方城堡必须构成**等边三角形**（任意两方间距相等）、
矿点绕质心精确 120° 旋转对称、三方建造区等面积且互不重叠、岩石近似旋转对称（格点取整，容差 1.2 格）。

注意**不同地图的实际难度差异不小**（同一档下，开阔地对玩家最有利、双通道最难），
这是地形带来的自然差异，不是 bug。跑批用 `ZW_MAP=n` 单独看某张图、`ZW_PLAYERS=2|3` 切人数。
