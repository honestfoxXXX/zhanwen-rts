# 视觉与音效打磨方案 · 执行设计

> 现状自评：视觉 10/100。根因不是缺贴图文件，而是：
> ① 精灵绘制层数少（平涂 + 单层阴影，无材质、无边缘光）；
> ② 场景没有生命感（无树、无水、无云影、无闲时动画、无氛围）；
> ③ 战斗表现几乎没有动画（攻击无动作、死亡一闪即逝、行军无扬尘）；
> ④ 音效是单层合成音，无环境声、无音乐、无层次混音。
>
> 技术路线：**继续零资源程序化绘制**。理由：相机有 8 倍缩放，矢量在任意放大倍率下依然锐利，
> 位图贴图放大即糊；且零资源是 Capacitor 打包与 76KB 体积优势的根基。
> 质量跃升的三个技术抓手：**精灵缓存**（预渲染换绘制预算）、**多层光影**（受光/暗面/边缘光/投影方向统一）、
> **时间驱动动画**（闲时呼吸/旗幟/炉火/云影全部走 time 正弦，零分配）。
> 预期：A1→A7 全部落地后整体观感 10 分 → 75-80 分档。

---

## A1 场景生命感（观感回报最大的一层）

| 项 | 做法 |
|---|---|
| **树丛** | 程序化乔木 2-3 种变体：树干（深棕梯形+根散）+ 三层树冠（大圆 0.85 深绿 → 0.65 中绿偏移 → 0.4 亮绿高光簇 + 2-3 个光斑），带统一方向投影。分布在地图边缘带、路径两侧、岩石群间隙——**不参与阻挡、不可选中**（纯装饰，写在 bg 预渲染里 + 少量近景树单独绘制在单位层之上树冠？——简化：全部入 bg 预渲染，避开出生/矿/路） |
| **云影** | 4-6 团大型柔和椭圆（半径 300-600，rgba(10,20,30,0.06)），按 time 慢速漂移（速度 ~12px/s，方向一致），渲染在地面之上、单位之下。运行时绘制（每帧 6 个 ellipse，成本可忽略）——大地图上云影飘过是"活世界"的最大单笔收益 |
| **草地质感** | bg 预渲染加密：草甸斑 ×3、草茎 ×4、碎石 ×3、野花 ×2（数量按 3840² 已扩过一轮，再提密度 + 提两层色阶），加几片**干枯草地色块**（偏黄 rgba 变体）打破均匀绿 |
| **水域**（中央关隘/开阔平原各加一条） | 河流曲线带：深水 rgba(30,60,90,0.85) + 岸线浅滩 rgba(90,120,100,0.5) + 运行时水面亮纹（沿河 3-4 段白色短划线按 time 平移闪烁）。河流**参与阻挡**（寻路 mark），桥/浅滩留通路——增加地形战术价值。工作量偏大，放 A1 末位，超时则砍 |
| **氛围点缀** | 出生点旁的小营地（帐篷+篝火烟）、路边孤石/木桩、王冠之地石阵加（旗帜残骸）。全部 bg 预渲染 |
| **光影统一** | 全场光源方向 = 西北（与现有单位受光面一致）；建筑/树/岩投影统一向东南偏移；边缘压暗保留 |

验收：静帧截图不看单位也能感到"这是被阳光照着的草原"，而不是绿色平涂。

## A2 建筑精绘二代 + 精灵缓存基建

- **精灵缓存**：新增 `spriteCache.ts`——按 (kind, type, side) 预渲染到离屏 canvas（含多层绘制），
  每帧只 `drawImage`；建筑/装饰先接入（数量少、细节重），单位在 A3 接入。受击闪白、低血量脉冲等动态层仍在运行时叠画。
- **建筑通用工艺**：基座石台（带透视的双层台）；墙体三层明暗（受光面/固有色/暗面）+ 边缘光（西北侧 1px 亮线）；
  石砖纹按行错缝；**损伤可视化**：hp <66% 出裂纹、<33% 裂纹加深 + 缺口 + 冒烟粒子（挂到 drawBuilding）。
- **城堡**：现构图上深化——塔顶加锥形顶（阵营色染边），门拱两侧火把（2px 火焰动画：双椭圆叠 time 闪烁），
  双塔都挂旗，墙体加苔藓斑；旗帜换双层（旗面明暗两片更飘）。
- **军营**：帐篷旁加道具（木箱 2、武器架：插着 3 把剑的架子），帐篷布加缝补补丁色块。
- **金矿**：矿车（木斗+两轮）停在轨道上，矿口挂一盏风灯（暖光点）。
- **箭塔**：塔身加高 10%，顶部石台出檐，塔窗透暖光，旗保留。
- **施工表现**：X 脚手架 → 真脚手架（四根立柱 + 横板 + 吊绳），进度条保留。
- 验收：三种血量状态截图（满/中/残），残血必须有"打烂了"的观感。

## A3 单位精绘二代（含动画）

- **精灵缓存**：单位按 (type, side) 预渲染本体（含武器道具、明暗、描边），每帧 `rotate + drawImage`。
  缩放锐利无忧（矢量重绘仅在缓存失效时）。
- **闲时动画**：呼吸（body scale 0.97~1.03 正弦，频率按 type 错开）替代部分 bob；弓手待机搭箭姿势。
- **行军**：步伐（两脚交替小线段，频率 = 速度）+ 行军扬尘（行进单位每 0.3s 冒一颗土色小粒子，40 人口大军=可见的尘尾——大军过境的观感核心）。
- **攻击动画**：近战挥砍（武器绕支点 -35°→+25° 快扫 0.12s，替代现在的静态剑）；弓手放箭瞬间弦回弹（弓形变平一帧）；
  骑枪冲锋（骑士冲锋时枪放平）；重装挥锤（对建筑攻击时锤头弧线）。
- **死亡**：现在一闪即逝 → 新增"倒地渐隐"：死亡瞬间本体按朝向倒下（旋转 90° + 压扁）+ 灰化渐隐 0.9s + 尘土圈；
  大型单位（重装/近卫/投石车）残留 3s 淡残骸（纯视觉，随 fx 列表清理）。
- **受击**：受击闪白 2 帧（命中方闪烁），配合现有火花。
- 验收：3x 特写录屏/连拍——行军有尘、攻击有动作、死亡有尸体，三件事缺一不可。

## A4 特效升级

- **抛射物系统**：投石车/弓手弹道加**高度弧线**（绘制时 y 减去 sin(t·π)·arc，投石车 arc 大）+
  **地面影子**（椭圆贴地按弧线移动）——投石车石弹划过天际带影子是"高级感"的最大单项。
- **命中分级**：命中火花已有 → 加命中冲击圈（小双环）与碎屑（击中建筑溅石屑、击中单位溅血色尘—— medieval 可用灰白"尘"替代血，保持过审友好）。
- **建筑坍塌**：城堡/建筑死亡从单圈爆炸 → 分阶段：结构闪崩（3-4 块大碎块抛物线飞散 + 2 层尘云 + 余烟 2s）+ 屏幕震动分级（大建筑震幅 8）。
- **法阵/增益**：暂无（无 buff 系统）。
- 粒子上限 220 → 400（fx 列表改为按 dur 排序的池，避免 shift 抖动）。

## A5 HUD 羊皮纸化

- 面板：程序化羊皮纸纹理（底色 + 低频噪点 + 四角花纹角饰），替代纯色圆角板；金边双线框。
- 按钮：石板底 + 金色描边 + 按下内凹；禁用态灰化。卡槽加冷却/进度时金色描边呼吸。
- 顶栏：资源图标加小衬底徽章；军力条加边框刻度。
- 小地图：羊皮纸边框 + 金角饰。
- 全部仍程序化（噪点用固定种子），样式集中在 styles.css + 少量 canvas 绘制。

## A6 音效升级（仍是 WebAudio 合成，无资源文件）

| 事件 | 升级 |
|---|---|
| 剑刃交锋（近战命中） | 金属 ring：短促方波+高频衰减正弦（FM 感），音高 ±随机，命中节流 80ms |
| 弓弦放箭 | 现有 shot 升级：弦"绷"（短噪声脉冲）+ 箭啸（带通扫频）双段 |
| 投石车 | 三段：发射闷响（低频 thump）→ 飞行风声（带通噪声随弧线音量起伏）→ 落地碎石（宽频 crunch + 低频尾） |
| 建筑坍塌 | 现有 boom 升级：低频 82→60 下沉 + 两段碎石滚落尾音 |
| 行军 | 大部队行进的低频脚步层（节流 400ms，随人口数调音量）——可选，避免嘈杂 |
| 金矿建成 | 金币"叮"声（两个高频正弦泛音叠） |
| 环境 | 环境风声（低通粉噪声循环，音量 0.03）+ 白日鸟鸣（随机间隔的短啾声，距中心衰减）——战场紧张时自动压低 |
| 动态混音 | 战斗音事件密度 → 环境声 duck（战斗越激烈环境越低）+ 主音量微压缩更紧 |

## A7 生成式音乐（可选开关，独立里程碑）

- 程序化环境音乐：多里安/爱奥尼亚五声阶的**拨弦乐句**（Karplus-Strong 简化：短噪声突发 + 调谐低通 = 拨弦音色），
  随机旋律生成器（每 4-8 秒一句，音程白名单内随机走步），底鼓/军鼓仅在战斗时进入。
- 双状态：和平主题（缓慢、稀疏）↔ 战斗主题（加鼓 + 密度提升），按"己方建筑受袭"事件切换，战后 20s 回落。
- 菜单/结算各一段固定短乐句。
- 默认音量 0.25，设置里可关。风险：生成式音乐容易"随机感"——用固定乐句库+变奏而非纯随机，写 3-4 个 motif 手工调。

## 性能守则（全程生效）

- 每帧世界渲染预算 ≤ 4ms（中端手机）：单位/建筑走精灵缓存 1 次 blit；云影/水纹 ≤ 10 个 ellipse；
  粒子池上限 400；A* 已有 guard；无逐帧分配热点（sort 复用数组）。
- bg 半分辨率维持；精灵缓存画布总量 = 类型×阵营 ≈ 10×3 张 96px 级别，内存可忽略。
- 每个里程碑用 `performance.now()` 包一帧渲染计时，>6ms 即回退该里程碑的最贵子项。

## 明确不做

- 不引入图片/音频资源文件（保持零资源与离线可用）。
- 不做像素画风转向（现有矢量风格已成型，转向等于重画全部）。
- 不做天气/昼夜系统（后续独立立项）。
- 不做伤害数字飘字（信息噪音，与极简 HUD 冲突；如实机想加再议）。

## 与下一轮（科技分档）的顺序建议

两份方案互不阻塞。建议顺序：**先 A1+A2（场景与建筑，观感收益最立竿见影）→ 科技兵种轮 → A3-A7 分批补**。
原因：精灵缓存基建（A2）做完后，新兵种（4 个）直接以缓存方式接入，避免先用旧管线画一遍再迁移。
